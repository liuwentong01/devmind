# DevMind 启动与部署指南

本文覆盖：本地开发调试、依赖中间件、各阶段（P0~P6）所需环境、容器化与 K8s 部署。

> 文中的业务 curl 默认针对 `APP_ENV=local`。非本地环境必须使用 `X-API-Key`，管理接口使用独立管理 key；GitHub/Alert Webhook 分别使用 HMAC/Bearer 验证。生产 Go/No-Go 条件见 [`生产上线检查清单.md`](生产上线检查清单.md)。

---

## 一、整体架构与端口速查

| 组件 | 技术 | 默认端口 | 说明 |
|---|---|---|---|
| 后端 API | FastAPI (uvicorn) | `8000` | REST + SSE |
| 异步 Worker | ARQ | — | 处理 P2/P3 异步任务，无端口 |
| 前端 | React + Vite | `5173` | 开发服务器，`/api` 代理到 8000 |
| PostgreSQL + pgvector | — | `5432` | P1 RAG 向量库 + 业务库 |
| Redis | — | `6379` | ARQ 队列 broker + 跨副本成本聚合 |
| Neo4j | — | `7474`(UI) / `7687`(Bolt) | P5 代码图谱 |
| Langfuse | — | `3000` | LLM 可观测（可选） |

> 各阶段对中间件的依赖不同，**最小只跑 P0 时无需任何中间件**。见下表。

| 阶段 | 必需中间件 | 必需配置 |
|---|---|---|
| P0 通用对话 | 无 | LLM Key |
| P1 知识答疑 | PostgreSQL(pgvector) | LLM Key + Embedding Key |
| P2 代码审查 | PostgreSQL(pgvector) + Redis（webhook 路径） | LLM/Embedding Key + GitHub Token（回写时） |
| P3 告警根因 | Redis（仅 webhook 路径） | local/test 可 mock；生产需真实证据源 |
| P4 需求拆解 | PostgreSQL | Atlassian；仅 local/test 可 dry-run |
| P5 代码理解 | Neo4j | LLM Key |
| P6 工程化 | Redis（生产成本聚合） | Langfuse（追踪/评测上报时，可选） |

## 二、本地开发调试

### 1. 起依赖中间件（按需）

```bash
# 全部起（PG/pgvector + Redis + Neo4j + Langfuse）
docker compose -f deploy/docker-compose.yml up -d

# 或只起需要的，例如只跑 P1：
docker compose -f deploy/docker-compose.yml up -d postgres
# 跑 P5：
docker compose -f deploy/docker-compose.yml up -d neo4j
```

验证：

```bash
docker compose -f deploy/docker-compose.yml ps
```

### 2. 后端

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -e .                 # 或：uv pip install -e .
cp .env.example .env             # 编辑 .env 填 Key（见下文「环境变量」）
alembic upgrade head              # 首次建库及 schema 变更后执行
uvicorn app.main:app --reload --port 8000
```

验证：

- 存活检查：<http://localhost:8000/api/health/live>
- 就绪检查：<http://localhost:8000/api/health/ready>
- 接口文档（Swagger）：<http://localhost:8000/docs>

> 本地启动仍保留 `create_all` 作为开发兜底，但正常路径必须先执行 Alembic，避免产生无版本标记的 schema。若未起 PostgreSQL，会打印 `db_init_skipped` 警告但**不影响 P0 启动**。

### 3. 异步 Worker（P2/P3 的 webhook/异步路径才需要）

另开一个终端：

```bash
cd backend && source .venv/bin/activate
arq app.workers.worker.WorkerSettings
```

> 这一个 worker 同时处理代码审查（P2）和告警根因（P3）任务。需要 Redis 运行中。

### 4. 前端

```bash
cd frontend
npm ci
npm run dev                      # http://localhost:5173
```

Vite 已配置把 `/api` 代理到 `http://localhost:8000`，前后端分离开发无需处理跨域。

## 三、环境变量说明（backend/.env）

完整模板见 `backend/.env.example`。关键项：

### LLM（必填至少一个厂商 Key）

```dotenv
LLM_DEFAULT_MODEL=deepseek/deepseek-chat   # 默认主力模型
DEEPSEEK_API_KEY=sk-xxx                      # 对应厂商 Key
# 可切换：dashscope/qwen-max(+DASHSCOPE_API_KEY) / zhipuai/glm-4(+ZHIPUAI_API_KEY)
```

### Embedding（P1 知识答疑必填）

```dotenv
EMBEDDING_MODEL=dashscope/text-embedding-v3
EMBEDDING_DIM=1024            # ⚠️ 必须与模型实际维度一致，换模型要重建向量表
DASHSCOPE_API_KEY=xxx
```

> 维度对照：通义 text-embedding-v3=1024 / 智谱 embedding-3=2048 / OpenAI text-embedding-3-small=1536。

### 数据库 / 缓存

```dotenv
DATABASE_URL=postgresql+psycopg://devmind:devmind@localhost:5432/devmind
# 生产迁移用独立 DDL 角色；本地留空即回退到 DATABASE_URL
MIGRATION_DATABASE_URL=
REDIS_URL=redis://localhost:6379/0
```

### 代码审查（P2，可选）

```dotenv
GITHUB_TOKEN=                  # 回写 PR Review 需要 repo 权限
GITHUB_WEBHOOK_SECRET=         # 与 GitHub Webhook 设置里一致
```

### 告警根因（P3，本地可选）

```dotenv
PROMETHEUS_URL=
LOKI_URL=
DEPLOY_REPO=                   # 形如 owner/repo，关联近期发布
IM_WEBHOOK_URL=                # 飞书/Slack 机器人 webhook
RCA_MAX_ITERATIONS=2
RCA_CONFIDENCE_THRESHOLD=0.75
```

> mock 只在 local/test 使用；生产缺少或无法查询证据源时会明确标记不可用。

### 代码理解（P5）

```dotenv
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=devmind-neo4j
CODE_INDEX_MAX_FILES=800
```

### 需求拆解（P4）

```dotenv
ATLASSIAN_BASE_URL=            # https://your.atlassian.net
ATLASSIAN_EMAIL=
ATLASSIAN_API_TOKEN=
JIRA_DEFAULT_PROJECT=
ALLOW_JIRA_DRY_RUN=true        # 仅 local/test；生产强制 false
```

### 可观测（可选）

```dotenv
LANGFUSE_PUBLIC_KEY=
LANGFUSE_SECRET_KEY=
LANGFUSE_HOST=http://localhost:3000
```

## 四、按阶段快速验证（冒烟测试）

> 起好后端后，用 curl 验证；或直接用前端页面。

```bash
# P0 通用对话（会调用工具）
curl -N -X POST http://localhost:8000/api/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"现在几点了？算一下 12*(3+4)"}]}'

# P1 先入库再问答（需 PostgreSQL + Embedding Key）
curl -X POST http://localhost:8000/api/knowledge/documents \
  -H "Content-Type: application/json" \
  -d '{"title":"请假制度","content":"请假需提前一天在 OA 提交，病假需医院证明，年假每年10天"}'
curl -N -X POST http://localhost:8000/api/knowledge/query/stream \
  -H "Content-Type: application/json" -d '{"question":"病假需要什么材料？"}'

# P2 手动审查（无需 GitHub）
curl -N -X POST http://localhost:8000/api/review/stream \
  -H "Content-Type: application/json" \
  -d '{"diff":"diff --git a/a.py b/a.py\n@@ -1 +1 @@\n-x=1\n+x = 1"}'

# P3 根因分析（仅 local/test 可使用 mock）
curl -N -X POST http://localhost:8000/api/incident/analyze/stream \
  -H "Content-Type: application/json" \
  -d '{"alertname":"HighMemoryUsage","service":"order-service","severity":"critical","description":"内存超95%"}'

# P4 拆解（local/test 可配置 dry-run；生产必须接 Jira）
curl -X POST http://localhost:8000/api/requirement/plan \
  -H "Content-Type: application/json" \
  -d '{"prd_text":"用户可用积分兑换商品；后台配置商品","project":"DEV"}'

# P5 索引本项目后端 + 问答（需 Neo4j）
curl -X POST http://localhost:8000/api/codebase/index \
  -H "Content-Type: application/json" \
  -d '{"repo":"devmind","path":"'$PWD'/backend"}'

# P6 成本统计
curl http://localhost:8000/api/admin/cost
```

## 六、容器化部署

### 构建镜像

```bash
docker build -t devmind/backend:verify backend
docker build -t devmind/frontend:verify frontend
```

- 后端镜像使用带哈希锁文件且以 UID 10001 运行，包含 Alembic migration；API 与 worker 共用镜像。
- 前端镜像用 `npm ci` 构建并以非 root nginx 运行。共享服务 key 由 nginx 运行时从 Secret 注入，不会编译进 JS。
- 单机生产参考 `deploy/docker-compose.prod.yml`；它只编排无状态应用，要求 TLS 托管数据库/Redis/Neo4j、显式密钥和不可变镜像。

## 七、Kubernetes 部署

严格按 [`deploy/k8s/README.md`](../deploy/k8s/README.md) 的顺序执行：Secret/Config → versioned Alembic Job 并等待成功 → workloads → PDB/HPA/NetworkPolicy → 最后启用已配置 OIDC/TLS 的 Ingress。禁止在 migration 成功前启动新版本 API。

主站 UI/API 强制 OIDC；Webhook 使用独立域名与精确路径。上游 TLS、真实密钥、代理 CIDR、只读代码卷、备份恢复和 Metrics Server 都是部署前置条件，不是清单中的默认占位值。

## 八、常见问题排查

| 现象 | 排查 |
|---|---|
| 启动报 `db_init_skipped` | PostgreSQL 没起 / `DATABASE_URL` 不对。只跑 P0 可忽略 |
| P1 入库报 embedding 模型错误 | `EMBEDDING_MODEL` 名称或 Key 不对；确认 LiteLLM 对应厂商命名 |
| P1 检索维度不匹配 | `EMBEDDING_DIM` 与模型/schema 不符；先备份，再编写显式 Alembic 迁移并重新向量化，不能在生产直接删表 |
| P2/P3 webhook 入队失败(503) | Redis 没起，或 worker 没启动 |
| P5 索引报 503 | Neo4j 没起 / `NEO4J_*` 配置不对 |
| P4 confirm 报 thread_id 无效 | 检查计划是否过期、已被确认，或数据库 migration/连接是否正常 |
| SSE 不流式/卡住 | 反代层未关闭缓冲（nginx `proxy_buffering off`） |
| 费用显示 $0 | 锁定版本的 LiteLLM 本地价格表可能未包含该模型；token 仍统计，正式结算以供应商账单为准 |
