# DevMind 源码注释与使用示例索引

本页是仓库级源码导航。各手写模块会在文件头说明职责、调用关系、典型用法和生产边界；本页负责把这些局部说明串成完整阅读路径。

## 1. 注释覆盖规则

### 会维护注释的文件

- Python/TypeScript/TSX 手写源码；
- Dockerfile、nginx、Compose、Kubernetes、GitHub Actions；
- `.env.example`、TOML、INI、ignore/editor 配置；
- Alembic migration 与测试；
- README 和设计/部署文档。

### 不直接写注释的生成或机器格式

| 文件 | 原因 | 正确维护方式 |
|---|---|---|
| `backend/requirements*.lock` | pip-compile 生成，手改会破坏 hash/依赖图 | 修改 `pyproject.toml` 后重新生成并审计 |
| `frontend/package-lock.json`、根 `package-lock.json` | npm 生成，JSON 不支持注释 | 修改 package.json 后运行 `npm install`/受控升级 |
| `frontend/tsconfig*.tsbuildinfo` | TypeScript 增量构建缓存 | 可删除重建，不作为源码阅读入口 |
| `backend/app/eval/datasets/*.json` | 评测数据，标准 JSON 不允许注释 | 在 `eval/run_eval.py` 与本文说明字段语义 |
| `package.json`、`tsconfig.json` | 工具消费的 JSON | 用 scripts 名称、相邻配置注释和本文解释 |

不要为了“每个文件都有注释”向 JSON 添加非标准字段，也不要直接编辑 lock。注释的目标是降低理解成本，不是增加无效行数。

## 4. Backend 文件地图

### 应用装配与核心

| 文件/目录 | 先理解什么 |
|---|---|
| `app/__init__.py` | 导入阶段禁止 LiteLLM 拉取可变价格表 |
| `app/main.py` | middleware、router、异常处理、启动/关闭资源的总装配 |
| `app/core/config.py` | local 易用与生产 fail-closed 的分界 |
| `app/core/security.py` | API key、body/header、路径和安全响应头 |
| `app/core/db.py` | AsyncSession、rollback、连接池、revision/vector 校验 |
| `app/core/logging.py` | JSON/控制台结构化日志 |
| `app/core/observability.py` | Langfuse 可选追踪与安全关闭 |

### HTTP 边界

`app/gateway/` 只处理协议：输入依赖、HTTP 状态、SSE 事件、Webhook 验签与业务层调用。`app/schemas/` 定义严格请求/响应和资源上限。新增接口时不要把大型 Prompt、数据库算法或第三方协议塞进 route。

### Agent 与 Kernel

| 目录 | 作用 |
|---|---|
| `app/agents/knowledge_qa` | P1 `retrieve → generate` |
| `app/agents/code_review` | P2 规则检索与 Review Prompt |
| `app/agents/incident_rca` | P3 并行取证、分析/验证循环与结论 |
| `app/agents/requirement` | P4 只负责生成提议；确认状态在数据库 |
| `app/agents/code_understanding` | P5 图谱上下文与影响解释 |
| `app/kernel/llm` | 统一模型创建、timeout/retry/token |
| `app/kernel/rag` | 分块、Embedding 校验、向量检索 |
| `app/kernel/queue.py` | ARQ pool 与稳定 Job ID |
| `app/kernel/requirement_store.py` | CAS lease、fingerprint、checkpoint、清理 |
| `app/kernel/graph` | tree-sitter 扫描解析与 Neo4j 原子替换 |
| `app/kernel/cost.py` | 内存/Redis 多副本成本聚合 |
| `app/kernel/tools` | P0 最小工具与 AST 安全计算 |

### 外部集成与 Worker

`app/integrations/` 负责 GitHub、Jira、Confluence、Loki、Prometheus 和 IM 的协议细节。每个集成都应说明认证、timeout、响应大小、重试、日志脱敏及 local mock/生产行为。

`app/workers/` 是独立进程入口，不能假设 API 已初始化连接。统一运行：

```bash
cd backend
arq app.workers.worker.WorkerSettings
```

### 数据库与迁移

```text
alembic/versions/20260815_0000  知识库基线
→ 20260815_0001               唯一约束、source 索引、Requirement 状态
→ 20260815_0002               concurrent HNSW cosine 索引
```

使用：

```bash
cd backend
alembic heads
alembic upgrade head
alembic current
```

非本地应用不会自动建表；migration 失败必须停止发布。

## 5. Frontend 文件地图

| 目录 | 作用 |
|---|---|
| `src/main.tsx` | Provider 装配入口 |


## 6. Deploy 文件地图

### 本地

`deploy/docker-compose.yml` 只启动 PostgreSQL/pgvector、Redis、Neo4j、可选 Langfuse，使用开发默认凭据，禁止用于生产。

### Production Compose

`deploy/docker-compose.prod.yml` 只运行 migration、backend、worker、frontend；数据服务必须外置。示例：

```bash
docker compose --env-file /secure/devmind.env \
  -f deploy/docker-compose.prod.yml config --quiet
docker compose --env-file /secure/devmind.env \
  -f deploy/docker-compose.prod.yml up -d
```

### Kubernetes

推荐应用顺序：

```text
namespace → serviceaccount → config/secret
→ migration（等待完成）
→ backend/worker/frontend
→ pdb/hpa/networkpolicy
→ 最后 ingress
```

详细命令和必改项见 `deploy/k8s/README.md`。YAML 是安全参考基线，不会自动提供企业 OIDC、托管数据库、证书、备份恢复和 SLO。

## 8. 新增代码时的注释模板

Python 模块建议写清：

```python
"""模块解决的问题与在调用链中的位置。

典型流程：入口 → 本模块 → 下游。

使用示例：
    result = await public_function(...)

生产边界：说明状态、副作用、超时、重试、幂等或安全假设。
"""
```

注释应该回答“为什么”，例如为何需要两次 SHA 校验、为何只 flush 不 commit、为何生产拒绝 mock。不要给 `count += 1` 之类显然代码逐行翻译。
