# DevMind 使用说明

DevMind 是一个 AI 研发效能智能体平台：5 个垂直业务 Agent 之外，还提供通用对话和成本治理入口。本文面向**使用者**，教你如何用每个功能。

> 开发者 / 部署相关请看 [启动与部署指南](启动与部署指南.md)。

---

## 快速开始

1. 打开平台首页（本地默认 <http://localhost:5173>），左侧是功能导航。
2. 默认进入「知识答疑」。各功能页都能独立使用。

界面布局：顶部是平台标题，左侧导航栏，右侧是各 Agent 的工作区。

---

## 功能一览

| 导航入口 | 能做什么 | 适用场景 |
|---|---|---|
| 知识答疑 (P1) | 基于你上传的文档回答问题，带来源引用 | 团队知识沉淀、新人答疑、制度查询 |
| 代码审查 (P2) | 对一段代码改动给出审查意见 | PR/MR 评审、自查代码 |
| 告警根因 (P3) | 输入告警，自动分析最可能的根因 | 线上故障定位、On-call |
| 需求拆解 (P4) | 把 PRD 拆成开发任务，确认后建 Jira | 需求拆分、排期、建任务 |
| 代码理解 (P5) | 索引代码仓库后问答 + 改动影响分析 | 接手老项目、评估改动风险 |
| 成本治理 (P6) | 查看 LLM 调用的 token 与费用 | 用量监控、成本管理 |
| 通用对话 (P0) | 普通对话 + 调用内置工具 | 体验 Agent 工具调用 |

## 1. 知识答疑 (P1)

**用途**：把文档喂给它，之后基于这些文档回答问题，并标注答案来自哪篇文档。

**怎么用**：

1. 左侧「知识文档」区：填**标题** + **正文**，点「入库」。系统会自动把文档切块并向量化。
2. 入库后文档出现在下方列表（显示切片数），可删除。
3. 右侧「知识问答」区：输入问题点「提问」。
4. 回答会**流式输出**，下方「引用来源」展示用到的文档片段（含相似度）。

**提示**：

- 答案只基于已入库文档；资料不足时它会明说「无法回答」，不会乱编。
- 可以入库多篇文档，问答会跨文档检索最相关的内容。

---

## 2. 代码审查 (P2)

**用途**：粘贴一段代码 diff，得到结构化的审查意见（含严重级别）。

**怎么用**：

1. 左侧粘贴 `git diff` 文本（不确定格式可点「填入示例」体验）。
2. 点「开始审查」，右侧流式输出审查意见。
3. 意见包含：总体结论（建议合并/修改后合并/不建议合并）+ 分级问题（🔴阻塞 / 🟡建议 / 🟢优化）。

**进阶（团队规范）**：

- 审查会参考「团队审查规范」。把规范作为文档，在**知识答疑**页入库（`source` 标识为 `review-rule`），审查时会自动检索这些规范作为依据。规范越多，审查越贴合团队习惯。

**自动化（需开发配置）**：配置 GitHub Webhook 后，PR 创建/更新会自动触发审查并把意见回写到 PR 评论，无需手动操作。

---

## 3. 告警根因 (P3)

**用途**：输入一条告警，Agent 自动并行拉取日志/指标/近期发布，分析出最可能的根因。

**怎么用**：

1. 填写告警信息（告警名、服务、级别、描述），或直接用预置示例。
2. 点「开始根因分析」。
3. 左侧「分析进度」实时显示步骤：并行拉取 → 生成假设 → 验证假设（可能多轮）→ 生成报告。
4. 右侧流式输出**根因报告**：最可能根因、推断依据、可疑的发布 commit、建议的处理动作。

**提示**：

- 只有 `local/test` 环境在未接入真实监控时会使用内置示例数据；非本地环境会明确报告证据源不可用，不会伪造证据。
- 接入真实 Prometheus/Loki/GitHub 后（开发配置），分析基于真实数据。
- 配置告警 Webhook 后，监控系统告警可自动触发分析并推送到 IM 群。

---

## 4. 需求拆解 (P4)

**用途**：把 PRD 拆成可执行的前后端开发任务，**人工确认后**再写入 Jira。

**怎么用**：

1. 左侧粘贴 PRD 正文（或用预置示例），可填 Jira 项目 key 和 Epic。
2. 点「拆解任务」，Agent 提议一份任务清单出现在右侧表格。
3. **人工闸门**：在表格里直接编辑——改标题、改类型（前端/后端）、改点数、删除不需要的任务。
4. 满意后点「确认并写入 Jira」，任务才真正创建。

**重要**：

- 拆解阶段**不会**写任何东西到 Jira，只是提议。只有你点「确认」后才会创建。
- `local/test` 可显式开启 **dry-run**（演示模式），显示「已生成任务但未真正写入」。非本地环境禁止 dry-run：Atlassian 配置不完整时确认请求会失败，不会返回伪造的 Jira 成功结果。

---

## 5. 代码理解 (P5)

**用途**：索引一个代码仓库后，可以问它代码相关的问题，还能分析「改某个函数会影响谁」。

**怎么用**：

1. 左侧「索引仓库」：填**仓库逻辑名**（任意，如 `devmind`）+ **本地绝对路径**（如本项目的 `backend` 目录），点「构建代码图谱」。
2. 索引完成后显示统计（文件数 / 函数数 / 调用数）。
3. 右侧两个标签页：
   - **代码问答**：问「`index_repo` 这个函数做了什么」之类，回答会标注参考了哪些文件。
   - **影响分析**：填一个函数名（如 `retrieve`），列出所有（直接或间接）调用它的函数 —— 即改动影响面，并给出回归测试建议。

**支持语言**：Python / JavaScript / TypeScript / Java / Go。

**提示**：最适合拿来索引你接手的老项目，快速搞清楚结构和改动风险。

---

## 6. 成本治理 (P6)

**用途**：查看平台所有 LLM 调用累计的 token 用量和费用。

**怎么用**：

1. 进入「成本治理」页，自动展示总请求数、累计费用、按模型分组的用量表格。
2. 页面每 5 秒自动刷新。
3. 可点「重置计数」清零。

**提示**：国内模型通常没有内置定价，费用可能显示 `$0`，但 token 用量是真实统计的。

---

## 7. 通用对话 (P0)

**用途**：体验最基础的 Agent —— 普通对话，并能在需要时调用内置工具（查时间、做计算）。

**怎么用**：输入消息发送即可。例如问「现在几点了？再算一下 12×(3+4)」，会看到它调用工具（界面用 🔧 标签标出调用了哪个工具）并流式回答。

## 常见问题

| 问题 | 说明 |
|---|---|
| 知识答疑说"无法回答" | 说明已入库文档里没有相关内容，先入库对应文档 |
| 代码审查没参考团队规范 | 需先在知识答疑入库规范文档（source=review-rule） |
| 告警根因结果像"编的" | 未接真实监控时用的是示例数据；接入真实数据后更准 |
| 需求拆解点了确认但 Jira 没任务 | 先确认当前是否为显式开启 dry-run 的 `local/test`；非本地环境应查看 Atlassian 配置、权限和 worker 日志 |
| 代码理解问答说找不到 | 先在同一页「构建代码图谱」，且仓库名要一致 |
| 回答是一段段蹦出来的 | 这是流式输出（边生成边显示），正常现象 |

## 一句话总结

DevMind 把研发中重复、跨系统、需要上下文的活儿交给 AI：**查知识、审代码、定位故障、拆需求、读代码、管成本**。每个功能都能独立使用，打开对应页面按提示操作即可。
