# DevMind 能力演进与深度学习路线

> 目标：在现有 DevMind 平台（P0~P6）基础上继续演进，**深度学习 RAG / MCP / Agent Loop 三大主流技术**，参考市面 Agent 产品能力，切实解决研发日常痛点。

现状回顾：当前 P1 是最朴素 RAG（chunk→embed→余弦检索→生成），P0 是预置 ReAct，P1/P2/P3/P5 是固定 DAG，工具是直接封装的 Python 类（未走真 MCP 协议）。三块都还在「入门版」，下面是进阶演进。

---

## 一、RAG 深度进阶

当前是「玩具版 RAG」。生产级 RAG（Glean / Perplexity / Dify）远不止于此。建议按顺序逐个加，每个都是独立可学的知识点。

| 进阶能力 | 解决的痛点 | 对标 | 在 DevMind 怎么加 |
|---|---|---|---|
| **混合检索（Hybrid Search）** | 纯向量召不回精确关键词/专有名词/代码符号 | Glean、Elastic | pgvector 向量 + PostgreSQL 全文检索（`tsvector`）/ BM25，结果用 RRF 融合 |
| **Rerank 精排** | Top-K 召回有噪声，答案被无关片段干扰 | Cohere Rerank、bge-reranker | 方案里写了但未实现——召回 20 条 → bge-reranker 重排取 4 条 |
| **查询改写 / HyDE / 多查询** | 用户口语化提问与文档措辞对不上 | Perplexity | 检索前让 LLM 把问题改写/扩展成多个查询，并行检索后合并 |
| **Contextual / Parent-Document 分块** | 小块丢上下文，大块不精准 | Anthropic Contextual Retrieval | 检索小块、喂 LLM 时带父文档；或给每块加 LLM 生成的上下文前缀 |
| **GraphRAG** | 跨文档关系型问题（"A 和 B 的关联"）向量答不好 | 微软 GraphRAG | 复用 P5 的 **Neo4j**，抽实体关系建图谱，混合图遍历 + 向量 |
| **Agentic RAG** | 一次检索不够，需要多轮迭代检索 | Agent×RAG 核心 | 把 `retrieve` 做成**工具**，让 Agent 自己决定检索几次、改写查询、判断够不够答 |
| **引用核验（Groundedness）** | 防幻觉，确保每句话有出处 | 生产级问答必备 | 生成后用 LLM 校验每个 claim 是否被检索内容支撑，不支撑则标注 |
| **RAG 评估** | 不知道改完是变好还是变差 | RAGAS | P6 Eval 雏形扩成 RAGAS 四指标（faithfulness / answer relevancy / context precision / recall） |

> **学习价值最高**：① **Agentic RAG**（检索变成 Agent Loop 的一环，把 RAG 和 Loop 打通）；② **GraphRAG**（复用 Neo4j，学图谱 + 向量混合）。

## 二、MCP 真实落地

当前 GitHub/Jira/监控都是直接封装的 Python 类（注释写着"后续改造成 MCP"）——这正是深度学 MCP 的最佳切入点。MCP 是 2025 年起的事实标准（Cursor、Claude Desktop、Cline 都在用）。

| 能力 | 学到什么 | 痛点 |
|---|---|---|
| **把现有工具改造成真 MCP Server** | Server 端：tools / resources / prompts 三原语、stdio/SSE 传输 | 工具能被任意 MCP 客户端复用，不绑死在本平台 |
| **在内核做 MCP Client/Host** | Client 端：连接多 server、动态发现工具、注入 LangGraph | Agent 启动时自动发现可用工具，新增工具零改代码 |
| **接入社区现成 MCP Server** | 生态复用：filesystem、postgres、brave-search、fetch 等官方 server | 不用自己写，挂上就有几十个工具 |
| **MCP 工具权限/审批网关** | 安全：危险工具（写库、删文件）需人工授权 | 企业落地 MCP 的核心顾虑 |
| **动态工具路由** | 工具多了按语义/场景给 Agent 只挂相关工具 | 工具数百个时上下文塞不下 |

> **建议落地**：把 `integrations/github.py` 做成一个真正的 MCP Server（`mcp` Python SDK），再在 `kernel/` 写 MCP Client 管理器，让 P2 代码审查 Agent 通过 MCP 协议调用它。这样完整走通 **MCP Server + Client + Host** 三端。

## 三、Agent Loop 深度进阶

当前 P0 是预置 ReAct，P1/P2/P3/P5 是固定 DAG，P4 有 HITL。市面 Agent 的"聪明"主要来自更高级的循环模式。

| Loop 模式 | 解决的痛点 | 对标 / 论文 | 在 DevMind 怎么加 |
|---|---|---|---|
| **Reflection / 自我批判循环** | 一次生成质量不稳，需自我纠错 | Reflexion、Self-Refine | 生成 → critic 节点挑刺打分 → 不达标回炉重写，带迭代上限 |
| **Plan-and-Execute** | 复杂任务一步到位不行，要先规划再执行 | BabyAGI、LangGraph plan-execute | planner 拆步骤 → 逐步执行 → replan，比 ReAct 更省 token、更可控 |
| **ReWOO** | ReAct 每步都调 LLM 太贵 | ReWOO 论文 | 先一次性规划工具调用 DAG，再批量执行 |
| **多 Agent 协作（Supervisor/Swarm）** | 单 Agent 什么都干不专精 | LangGraph Supervisor、AutoGen、CrewAI | 一个 supervisor 调度多个专精 subagent（现有 5 个 Agent 可被统一编排！） |
| **长期记忆 + 情景记忆** | Agent 记不住跨会话偏好/历史 | Mem0、Zep、MemGPT | 向量库存长期记忆，每次对话前检索注入；代码审查记住团队偏好 |
| **Subagent 派生** | 主 Agent 把子任务甩给临时 subagent | Claude Code、Cursor Task | LangGraph 动态 spawn 子图 |
| **Computer Use / 浏览器自主操作** | 没有 API 的系统只能操作 UI | Claude Computer Use、OpenAI Operator | Playwright + 多模态 LLM，自主点击填表 |

> **学习价值最高**：① **Reflection 循环**（最通用，立刻提升 P1/P2 质量）；② **多 Agent Supervisor**（把已有 5 个 Agent 收编成"研发总管 Agent"，自然语言路由，对标 Devin）。

## 四、可新增的实用 Agent（市面对标 + 日常痛点）

| 新 Agent | 痛点 | 对标 | 主要技术 |
|---|---|---|---|
| **深度研究 Agent** | 调研一个技术/方案要翻几十个网页 | Perplexity、GPT Researcher | Agentic RAG + 联网搜索（MCP brave-search）+ Plan-Execute |
| **数据库问答 Agent（Text-to-SQL）** | 看数据要找数仓同学写 SQL | Vanna、Hex | Schema 注入 + 生成 SQL + 安全执行 + 自我纠错循环 |
| **会议纪要 / PRD 提炼 Agent** | 会议录音、长文档要人工总结 | Otter、Fireflies | 长文本分段摘要 + 结构化抽取 |
| **统一企业搜索 Agent** | 信息散在 Confluence/Jira/代码/IM | Glean | 多源 Hybrid RAG（直接升级 P1） |
| **运维操作 Agent（ChatOps）** | 查日志/重启/扩容要登跳板机 | PagerDuty AI | MCP 工具 + 审批网关（接 P3） |
| **PR 自动修复 Agent** | 审查发现问题还要人改 | Devin、Cursor | P2 + 代码编辑 + 跑测试的自我修正循环 |

## 五、推荐深度学习路线

按「学一个技术点 → 立刻用到 DevMind 真实场景」的原则，全程用 P6 的 Eval 量化每次改进效果（这是高手和调包侠的区别）：

1. **RAG 进阶**：先做 **Rerank + Hybrid Search**（立竿见影）→ 再做 **Agentic RAG**（把检索变成 Agent Loop 的工具，顺带串起 Loop）
2. **MCP**：把 `integrations/github.py` 改造成**真 MCP Server** + 内核加 **MCP Client**（彻底搞懂 MCP 三端）
3. **Agent Loop**：先加 **Reflection 循环**（升级 P1/P2 质量）→ 再做 **多 Agent Supervisor**（把 5 个 Agent 收编成总管）
4. 全程用 **Eval** 量化改进效果

这条路线下来，会把 **RAG（进阶检索）× MCP（工具协议）× Agent Loop（高级循环）** 三者在一个真实项目里彻底打通。

### 候选 P7 优先级（择一开始）

| 优先级 | 主题 | 一次同时深化 |
|---|---|---|
| 1 | **Agentic RAG + Rerank** | RAG + Agent Loop（改造现有 P1，见效最快） |
| 2 | **MCP 化改造** | MCP 三端（GitHub 工具做成真 MCP Server + 内核 Client） |
| 3 | **多 Agent Supervisor** | Agent Loop（把现有 5 个 Agent 收编成"研发总管"） |
